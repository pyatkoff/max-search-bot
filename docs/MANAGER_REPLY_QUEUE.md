# Точная очередь ответов Manager2

«Ответ не требуется» снимает потребность отвечать на уже показанное обращение.
Отметка сохраняет автора, время и границы сообщений клиента и запроса менеджера.
Её можно отменить. Новое сообщение клиента или отдельный новый запрос менеджера
снова создаёт ожидание; следующая отметка не отменяется старой кнопкой Undo.

Это отдельное решение об ответе. Оно не меняет прочитанность, назначение,
статус диалога, смену, задачи или состав вкладки «Мои». Диалог остаётся доступен
в своей обычной подборке. Операционные подборки ожидания используют единую
политику `ManagerReplyQueueService`; историческое время первого ответа остаётся
отдельной метрикой.

Таймер начинается с первого сообщения текущей серии без ответа. Следующие
сообщения серии его не обнуляют. При первоначальной передаче менеджеру отсчёт
идёт с передачи, без предыдущей беседы с ботом. После ответа или отметки новое
обращение начинает свой отсчёт. Источник времени — сохранённые часы записи;
возраст старых записей без достоверных часов явно неизвестен. Абсолютное время
интерфейса показывается в МСК.

Продолжительность — календарное время от сохранённого начала ожидания, включая
нерабочие часы. Интерфейс явно называет этот способ подсчёта; он не подменяет
его рабочим SLA и не меняет график менеджеров.

Полоса состояния остаётся видимой и без текущего ожидания. Необязательное поле
`activity_state` в существующем snapshot различает закрытый диалог, режим бота,
приостановленную доставку, ожидание менеджера, действующую отметку «Ответ не
требуется» и отсутствие активного ожидания. Неизвестный технический статус
показывается как неизвестный. Это вычисляемое представление существующих фактов,
без нового сохранённого состояния и без изменений списка Inbox.

Закрытие и режим бота показываются прежде состояний очереди. Для диалога
менеджера приостановка доставки имеет приоритет над отсутствием ожидающих
сообщений. «Ответ не требуется» является текущей причиной только пока отметка
покрывает обе границы: сообщения клиента и запрос передачи менеджеру. Иначе
автор и время сохраняются под подписью «Последняя отметка».

Отсутствие ожидающего ответа не означает «Ждём клиента» или выполнение обещания.
Даже успешно отправленное «уточняю, пришлю расчёт» завершает только технический
цикл ответа. Содержательный следующий шаг и задачи остаются у своих владельцев.
Старый snapshot без нового поля сохраняет прежнее отображение и управление;
неизвестный исход отметки и его проверка всегда остаются видимыми.

Старые записи «Ждёт менеджера» без сохранённого события передачи сохраняются
в очереди с неизвестным временем. Их можно явно отметить и отменить отметку;
историческое событие или время для них не выдумывается.

Новая отметка привязана к версии решения и текущим правам. Успешный ответ
менеджера покрывает только входящие, зафиксированные **до** отправки провайдеру:
вопрос, пришедший во время отправки, остаётся в очереди. Неудачная отправка,
ответ бота, чтение, смена статуса или назначения сами по себе не являются ответом.

Решения записываются в существующую ленту `conversation_events`. Миграция
`098_manager_reply_queue.sql` добавляет квитанции операций для защиты от повторов.
При потере ответа браузер сохраняет идентификатор операции отдельно для каждого
менеджера и диалога. «Проверить результат» только читает квитанцию. Если она ещё
не найдена, явное «Повторить сохранение» использует тот же идентификатор и
неизменный запрос; автоматического повторного сохранения нет.

Проверки используют искусственные диалоги: PHP/SQLite — решение, отмена,
границы и права; native MySQL — миграция и конкурентный доступ; Node — потеря
ответа, перезагрузка, смена диалога/аккаунта и сохранность редактора; настоящий
PHP shell в браузере — действие и таймер на 390/430/768/1440. Эти проверки не
подтверждают использование функции живым менеджером или физическим телефоном.
