# Full conversation analysis — owner request, 17 October 2026

The owner explicitly requested analysis of all accumulated current conversations,
followed by three knowledge scopes: AnyTour business knowledge, shared manager
communication practice, and the individual manager's knowledge and style.

## This execution

- Work from the current deployed/main SHA. No production application change,
  deployment, schema migration, message send, read marker, assignment, routing,
  shift, Metrika or neighbouring-project change is part of this operation.
- Use the dedicated one-shot branch workflow after its complete required tests,
  native MySQL read-only regression and crypto validation succeed.
- Send the self-contained PHP collector to the existing server interpreter on
  stdin; do not install collector files or create an HTTP export endpoint.
- Scope the configured current project; include all stored channels, open and
  closed conversations, complete stored text and events. Keep explicit tests
  identifiable for separate analysis.
- Capture a consistent read-only snapshot, upper IDs and expected/exported row
  counts. A failed bound, missing row, interrupted stream or inconsistent count
  fails the export. It must never be described as complete.
- Only owner-recipient age ciphertext and an aggregate manifest may leave the
  runner. Plaintext, key copies and temporary files stay private and are removed.
- Validate source/run/attempt, GitHub artifact digest, exact production SHA,
  capture freshness, age integrity and corpus coverage before analysis.

The recorder is a best-effort mirror. Complete database coverage does not prove
that every external messenger message was recorded. Attachment metadata is
counted; photo, voice, video and document contents require separate coverage.

## Analysis outputs

1. Exact corpus coverage: counts, channels, periods, authors, tests, media and
   known gaps; all business text conversations accounted for.
2. Client requests: directions, departure cities, dates/flexibility, party,
   budget basis, recurring questions, objections and confirmed stopping reasons.
3. Recorded journey: entry, meaningful request, manager request/assignment,
   first and subsequent replies, offers and recorded results. Unknown outcomes
   remain unknown. Silence is not an inferred refusal or completed sale.
4. Communication practices: useful patterns, repeated clarification, unresolved
   questions, promises and context-sensitive follow-up opportunities.
5. Source-backed knowledge candidates with author, evidence, time, scope,
   confidence and review state; contradictions and stale facts remain visible.

## Knowledge boundaries

| Scope | Contents | Owner and publication rule |
| --- | --- | --- |
| AnyTour | Approved services, business rules, destinations, product explanations and current operating terms | Owner/authorized editor approves; authoritative policies outrank a phrase in a conversation |
| Shared communication practice | Reviewed useful explanations, clarification patterns and handling of objections | Shared candidates are reviewed before becoming team guidance |
| Individual manager | Preferred wording, personal templates, corrections and working methods | Account-scoped; personal examples are not silently promoted into the shared base |

Client and trip facts remain attached to their own requests, not promoted into
general knowledge. Each manager-authored message is attributed to its actual
sender rather than the conversation's current assignee. Later corrections and
new trips must not silently overwrite older evidence.

No knowledge candidate becomes an automatic customer reply or an advertising
training signal merely because it was extracted. These outputs support the
already agreed funnel, advertising analysis, AI assistant and manager-help panel.
