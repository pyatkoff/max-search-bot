## Назначение

Установить первый фактически отказавший допуск в `ModeledConversionValueContract::candidate()`
для сохранённых `HOLD/SAVED_VALUE_UNAVAILABLE` двух completed ticks:

| --- | ---: | --- |
| A | 1795400583 | 2026-11-23 02:23:03 |
| B | 1795400885 | 2026-11-23 02:28:05 |

Операция закрепляет original activation `1795387176`, epoch
`5afe07ec09092f928926fb64543af19fd5ab14b921eab1d22cf82f0fba91669f`,
initial profile floor `17653`, проект AnyTour, counter `98615635`, goal `687941321`
и target `anytour_modeled_value_v2_max2`.

Выбор: original work → exact immutable profile ID. Новая версия того же subject
используется только для проверки текущего `access_status` и не заменяет исходный JSON.
Оба текущих допуска проверяются до любого исторического JSON, затем снова после
rollback. Native binding и owner/test exclusions совпадают с существующим контуром.

## Условия исполнения и объём

Настоящий владелец и допустимый оригинальный workflow подтверждаются неизменённым
после обычного выпуска canonical `resolve-consumer`. Хеши источников и конфигурации
проверяют происхождение и неизменность, сами по себе не предоставляют разрешение.
Используются существующие STANDBY_DEPLOY credentials и закреплённый host fingerprint.
Программа передаётся по stdin PHP; отдельный серверный файл не записывается.

Reader выполняет восемь SELECT данных: settings, original pair metadata, две скалярные
проверки доступа, два исходных JSON и две повторные проверки доступа. Оболочка дополнительно
выполняет двенадцать малых SELECT актуального проекта. Metadata имеет sentinel `LIMIT 3`;
при отсутствии ровно двух исходных строк чтение закрывается без частичного результата.
Рабочие пределы reader: 131072 байта на JSON, 278528 байт суммарно, 5 секунд;
каждый SELECT получает существующий MySQL hint `MAX_EXECUTION_TIME(250)`.
Общий authorizer ограничен 8 секундами, PHP — memory_limit 64M и execution_time 10;
транспорт ограничен 45 секундами. Эти ограничения не являются разрешением на повтор.

Основное чтение выполняется в READ ONLY snapshot с обязательным rollback. Нет DDL,
commit, изменения cursor/epoch/mode, запуска worker, формирования новой модели,
conversion upload или провайдерского запроса. V1, обе цели и рекламные кампании
операцией не изменяются.

## Объяснение результата

Диагностический проход строго сравнивает полный внутренний результат с настоящим
`candidate()` на обеих границах `[tick.started_at, work.recorded_at]`. Точный исходный
момент вызова worker не сохранён. Если он влияет на результат, вывод остаётся
`original_evaluation_time_unresolved`; текущий момент времени не заменяет исходный.

Вывод содержит только A/B, исходные времена tick/work, фиксированный gate/category,
70 разрешённых логических признаков и 12 ограниченных счётчиков. Идентификаторы,
source refs, тексты, ClientID, исходные JSON, денежные суммы и вероятности не выводятся.
Неожиданный bootstrap/PHP/PDO вывод подавляется; оболочка повторно проверяет точную
структуру результата перед сохранением receipt.

`no_admitted_estimate` является нейтральной категорией. Законное отсутствие оценки,
ошибка источника и временное ограничение различаются по конкретным предикатам,
а не по названию этой категории. Если исходный null не воспроизводится, результат
не объявляется доказанной причиной HOLD. Положительный candidate не даёт разрешения
на отправку: последующие V2 price/identity/binding/accounting gates здесь не запускаются.

4. Один раз создать ранее не существовавшую ветку `ops/max2-hold-pair-read-20261123`, указывающую
   непосредственно на текущий принятый main. Это запускает единственный оригинальный
   `.github/workflows/max2-hold-pair-read.yml`, job `diagnose`, attempt 1.
5. Прочитать и проверить исходный receipt, сопоставить причины A/B и представить вывод.
   Повторный run, удаление/пересоздание ветки, смена роли/контекста или ручной tick не допускаются.

Новый consumer не допускает workflow_dispatch, schedule или deployment tail. Он проверяет
единственный native run и фактически активный job, текущие main/branch и принятое приложение
до чтения и после него. Исторические audit carriers не заменяют этого допуска.

Обоснование отдельного подтверждения: пользователь разрешил один диагностический скрипт
через существующие операции, но готового reader среди зарегистрированных consumers нет.
Этот пакет добавляет регистрацию общего resolver и проходит новый SOURCE release.
